## 1. 产品背景与目标

### 1.1 背景

随着 Claude Code、GitHub Copilot Codex 等 AI 编程客户端的普及，国内开发者面临两个核心问题：

1. **接口不兼容**：Claude Code 使用 Anthropic Messages API，而国内大模型服务商（DeepSeek、通义千问等）主要提供 OpenAI 兼容 API，无法直接使用
2. **多 Provider 管理困难**：开发者可能同时使用多个模型服务商，需要统一管理 API Key、模型切换和故障转移

### 1.2 产品目标

SUGT 定位为 **AI 编程客户端的本地网关**，核心目标：

- **P0**：让 Claude Code / Codex 零配置接入国内大模型
- **P0**：提供统一的模型配置管理和故障转移能力
- **P1**：支持 Anhtropic ↔ OpenAI 协议自动转换
- **P1**：提供 GUI 和 CLI 两种操作界面
- **P2**：商店版支持 Claude Skills 发现和安装

### 1.3 目标用户

| 用户画像     | 典型场景                         | 核心需求               |
| -------- | ---------------------------- | ------------------ |
| AI 编程开发者 | 使用 Claude Code 写代码，需要调用国内大模型 | 一键接入、协议兼容          |
| 团队管理者    | 为团队统一管理模型接入                  | 集中配置、试用治理          |
| 技术负责人    | 评估和测试不同模型效果                  | 快速切换 Provider、连接测试 |

## 3. 功能需求详情

### 3.1 本地网关代理（F-01）

**需求描述**：在用户本机启动一个 HTTP 网关服务，接收 AI 客户端的 API 请求并转发到上游 LLM 服务。

**验收标准**：

| ID      | 验收项                                       | 预期结果                                       |
| ------- | ----------------------------------------- | ------------------------------------------ |
| F-01-01 | 默认监听 127.0.0.1:8787 启动                    | 端口成功监听                                     |
| F-01-02 | GET /health 返回运行状态                        | JSON：ok=true/false + active provider       |
| F-01-03 | GET /v1/models 返回模型列表                     | OpenAI 兼容格式                                |
| F-01-04 | POST /v1/chat/completions 转发到上游 OpenAI 服务 | 上游收到请求并返回正常响应                              |
| F-01-05 | POST /v1/messages 转发到上游 Anthropic 服务      | 上游收到请求并返回正常响应                              |
| F-01-06 | Anthropic → OpenAI 协议转换                   | Claude Code 可通过 SUGT 使用 OpenAI 兼容 Provider |
| F-01-07 | SSE 流式响应                                  | 客户端正常收到流式事件                                |
| F-01-08 | 故障转移：首选 Provider 5xx 时自动切换                | 请求被下一个 Provider 处理                         |
| F-01-09 | 故障转移：4xx 不重试                              | 直接返回 4xx，不切换                               |

**交互规则**：

- 启动网关前检查是否有启用模型，允许无模型启动（/health 返回 ok=false）
- 停止网关后所有请求无法转发

## 5. 用户交互流程

### 5.1 首次使用流程

```
下载 → 解压 → 双击 SUGT.exe
  ↓
自动创建 Documents/.sugt/ 配置目录
  ↓
进入控制台页（网关未启动状态）
  ↓
切换到"模型配置"页 → 点击"添加模型"
  ↓
弹窗选择"DeepSeek"预设 → Base URL 自动填充 → 输入 API Key → 保存
  ↓
回到控制台 → 点击"启动" → 状态变为"运行中"
  ↓
切换到"客户端"页 → 点击"Claude Code 一键接管"
  ↓
打开终端 → 正常使用 Claude Code → 所有请求走 SUGT
```

### 5.2 日常使用流程

```
启动 SUGT.exe（系统托盘常驻）
  ↓
检查网关是否运行（未运行则托盘启动）
  ↓
在终端使用 Claude Code / Codex 写代码
  ↓
需要切换模型时 → 模型配置页 → 设其他模型为默认 → 自动切换
  ↓
在流量面板查看使用情况
```

### 5.3 故障处理流程

```
客户端请求失败
  ↓
检查控制台 → 网关是否运行？
  ├─ 否 → 启动网关
  └─ 是 → 检查模型状态
      ├─ 不可用 → 测试连接 → 检查 API Key 是否正确
      └─ 可用 → 查看日志 → 请求是否成功转发？
          ├─ 否 → 检查网络/上游状态
          └─ 是 → 检查协议适配是否正确
```

## 6. 数据规范

### 6.1 配置目录结构

```
Documents/.sugt/
├── config.toml          # 主配置文件
│   ├── host             # 默认 127.0.0.1
│   ├── port             # 默认 8787
│   ├── failover_enabled # 默认 false
│   ├── autostart        # 默认 false
│   ├── [[providers]]    # 模型配置数组
│   │   ├── id           # UUID v4
│   │   ├── name         # 用户命名
│   │   ├── provider     # 服务商标识
│   │   ├── base_url     # API 地址
│   │   ├── api_key      # API Key
│   │   ├── model_name   # 模型名
│   │   ├── protocol     # openai / anthropic
│   │   ├── enabled      # true / false
│   │   └── status       # Unknown / Available / Unavailable
├── sugt.log             # 运行日志
├── trial-state.json     # 试用状态
└── store/               # 商店数据
    ├── repos.toml       # 仓库列表
    ├── settings.toml    # 商店设置
    ├── staged.json      # 暂存记录
    ├── mounted.json     # 挂载记录
    ├── skills/          # 暂存技能
    └── cache/           # Git 缓存
```

## 7. 术语表

| 术语       | 说明                                |
| -------- | --------------------------------- |
| Provider | 模型提供商配置，包含 API 地址、Key、模型名等        |
| 网关       | SUGT 启动的本地 HTTP 代理服务              |
| 故障转移     | 当前 Provider 不可用时，自动切换到备用 Provider |
| 协议适配     | Anthropic ↔ OpenAI 请求/响应的自动格式转换   |
| SSE      | Server-Sent Events，流式响应的传输协议      |
| 接管       | 将客户端的配置改为指向 SUGT 网关               |
| 技能商店     | 商店版的功能模块，管理 Claude Skills 的发现和安装  |
| 暂存区      | 技能下载后的本地存储目录                      |
| 挂载       | 将技能链接到 Claude Code 可识别的位置         |
| trial    | 试用版，有时效和机器绑定限制                    |
