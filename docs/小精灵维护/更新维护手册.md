### 4.2 为什么以前会出框、还会「高矮胖瘦」（v1.3.2 已修复）

这是**两个独立缺陷**，不是动作画坏了：

| # | 缺陷 | 修复前实测（已确认） |
| --- | --- | --- |
| 1 | **尺度不一** | Qwen-Edit / H3 每段把人物画得不一样大：源帧人物高 `588~767 px`（极差 30.4%），落包后 `215~275 px`（**极差 27.9%**，最矮 `celebrate`、最高 `error`）。旧归一化只对齐坐标系、不校正尺度 |
| 2 | **显示框外显示不全** | 逐帧扫 1000 帧 alpha 包围盒：**18 / 20** 个动作至少一边最小留白 `0~5 px`，右侧 `R0` 最普遍；`stretch` 伸展时人物宽从 116 涨到 160（画布满宽），`peek`、`typing`、`wake` 的手/发源帧就触到 `x=511`（512 画布右边缘） |

**为什么 0 留白会被看见**：三档窗口的 `contain` 全由高度主导，绘制高度正好等于窗口高度、上下 0 余量；旧 `background-position: right bottom` 又把立绘贴死右下角。再叠加 `lifted` 上移 `-10px`、`pet-hop -7px`、`pet-breathe / pet-poke` 轻微放大，最后被 `pet.css` 的 `.pet-stage { overflow: hidden }` 硬裁掉发梢 / 手 / 鞋。左边 28% 是气泡区，不是角色缓冲。

> 修复前逐动作留白表见《动作表》第三节「历史基线」；**v1.3.2 历史实测**见 `traces/精灵动作序列生产-20261110-131943.md`（最小留白 14px、框外实体 0.000%）；**v1.3.3 现行实测**见 `traces/精灵动作序列生产-20261110-152906.md`（`h_ref=176.0px`、最小留白 13px、极差 1.1%）与 `ASSETS.md §11.3.1`。

### 4.3 v1.3.2 定稿修法（**不重新生成、不裁人物**）

> **四问的明确答复（用户 2026-11-10 追问）**
> 1. **原始图没了吗？** 没丢。20 段 H3 补间视频与 master 全在 `SUGT_PET_WORK/videos/` 与 `keys/`，逐帧透明抠图结果永久缓存到 `cutouts/`；v1.3.2 那轮是 `512×768`、**零 ComfyUI 调用**。v1.3.3 仅 `wake` 改用 `640×768` 重生成（原因见 4.3.1），其余 19 段仍是旧视频；旧版全量视频仍备份在 `/tmp/sugt-pet-v132-backup/`。
> 2. **原始图有问题吗？** 图本身没坏。问题 100% 出在旧归一化：v1.3 用「全 1000 帧 bbox 中位数 +20px」做**硬裁切**，v1.3.1 改用「逐动作代表框 ± 90 分位外扩（再钳 25%/15%）」仍是硬裁切；`stretch` 的手臂、抬起的脚只要落在分位框外就被**永久切掉**，且模型每段把人物画得不一样大（源帧高 588~767）从没被校正。
> 3. **不能只改尺寸适配吗？** 不能只改窗口/CSS。放大窗口只能等比放大，不能把「已经裁掉的肢体」变回来，也不能把 20 个动作画得一样大。但**改人物尺寸不需要重生成**：改 `manifest.baseSize` 或 `do_frames()` 的 `safe_x/safe_y`，用缓存重跑 `--phase frames` 即可（分钟级）。
> 4. **必须重做吗？** 尺寸 / 留白 / 画布 / 命中框类**不必须**，离线 `--phase frames` 即可；但 **v1.3.3 发现「源画布本身把手指、发梢、鞋底裁掉」属于源像素缺失，离线怎么缩放都补不回来，必须重生成**。因此 v1.3.3 **只对 `wake` 一段**走 ComfyUI（`640×768` + 主图 0.78 + 四边门禁）；其余 19 段仍用 v1.3.2 的 `512×768` 旧视频，按用户要求「先记着、以后再优化」暂不重复付生成成本，见 4.3.1。只有这一类问题才值得付生成成本，见 4.4。

**A. 素材层 —— SCR-019 `do_frames()` 改为纯缩放 + 平移**（一次修全部 20 动作 / 1000 帧）

1. **不再 `crop()` 人物**。每动作取 50 帧稳健 `tight_box` 的**四边并集**作安全框；并集由定义覆盖每一帧的全部肢体，不做任何分位/百分比裁剪。并集框外只把色键噪点的 alpha 清零（人物像素一个不丢）。
2. 每动作以「四边中位数代表框高度」为 `core_h_i`，解一个**所有动作共用**的目标身高 `h_ref`：取 20 动作 × 上下左右四个方向共 80 个约束里的最小值。于是 `scale_i = h_ref / core_h_i`，**20 个动作的代表人物高度恒等于 `h_ref`** → 消除高矮胖瘦。
3. 每动作 50 帧共用**同一** scale 与 offset（动作内不抖动）；全体共用「脚底同线 + 水平居中」锚点（切换动作不跳位）；`su-blink` 走同一函数。
4. 画布四边预留透明安全边 `safe_x/safe_y = max(8, 画布×6%)`，`180×297`（0.606 < 绘制区约 0.643，`contain` 仍由高度主导，不会被二次缩小）。
5. **三条硬门禁**（不达标直接抛错，不进重编码）：最小四边留白 ≥6px、跨动作人物高度极差 ≤8%、**并集框外实体像素占比 ≤2%**（>2% 说明 `tight_box` 漏掉了真实肢体，必须停，防止「一截把动作中的某些部位截没了」）。
6. **抠图缓存 + 6 进程并行**：逐帧色键是纯 Python 逐像素循环（单帧约 1.9s），结果落 `cutouts/<动作>/*.png`；以后调人物尺寸 / 留白 / 画布，直接复用缓存秒级复跑，只有 `--recut` 才重新抠图。

**B. CSS 层 —— 窗口内侧安全边 + 水平居中**

| 改动 | 文件 | 现值 |
| --- | --- | --- |
| 新增 `--pet-inset-x` / `--pet-inset-y` | `src/pet/pet.css` `.pet-stage` | `8px` / `8px` |
| `.pet-figure` 用 inset 变量 | `src/pet/pet.css` | `top/right/bottom` 均内缩 |
| `.pet-loop` / `.pet-poster` / `.pet-blink` 定位 | `src/pet/pet.css` | `background-position: center bottom`（原 `right bottom`） |
| 命中框反算同步 | `src/pet/config.ts::figureHitRect` | `originX = rect.left + (width - drawW) / 2` |

`center` 而非 `right` 是为了 `scaleX(--face-x)` 镜像时左右对称。**改了 `background-position` 就必须同步改 `figureHitRect`**，否则穿透命中框整体偏左。

## 五、动作表与优先级分层

完整 20 条见《动作表.md》。这里只记**分层规则**（`AGENTS.md:79`）：

```
优先级 100 / 99   lifted / landing          拖拽三段（最高，必须压过任何网关态）
优先级 80 ~ 47    交互与自动专属动作        celebrate / disappointed / petted / poked /
                                          wake / welcome / greeting / wait /
                                          stretch / lookAround / peek / walk
优先级 30 ~ 26    网关状态类                typing / error / done / sleep / offline
优先级 0          idle                      兜底基态
```

**铁律**：交互 / 自动类必须排在状态类之上。曾经 `state` 类 priority 86–90 高于交互类，导致 `celebrate` 被 `done` 吞掉（单测 `done celebrate` 失败暴露）。`trigger: always` 只用于状态类；其余 `trigger` 必须等于动作名，由布尔 flag 驱动。

`posePriority[]` 必须与 `priority` 降序一致（C36 会校验）；`PET_ACTIONS` 由生成器按 priority 降序输出，`petState.ts` 直接 `.find()` 查表。
