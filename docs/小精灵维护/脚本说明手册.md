# 小精灵脚本说明手册

> **维护人**：孙测测　|　**日期**：2026-11-10　|　**适用**：SUGT 桌面精灵 v1.3
> **收录原则**：只收**实测跑通、v1.3 仍在用、可复现定版产物**的脚本。试片失败、早期 v0.7 链路、与精灵无关的脚本一律不收（清单见第四节）。
> **统一入口**：`scripts/petctl.py`（SCR-021）。所有命令也可直接执行 `scripts/` 下的同名副本。

## 一、通用约定

| 项 | 约定 |
| --- | --- |
| 解释器 | **`/usr/local/bin/python3.13`**（需 Pillow；系统 `python3` 没有 Pillow） |
| 工作目录 | 任意，脚本按 `__file__` 推导项目根；`petctl.py` 会 `cwd=项目根` |
| 参数化 | 路径走 `--root` / `--out` / `--source` / `--image`，不硬编码本机绝对路径 |
| 退出码 | `0` 通过 / `1` 检查不通过 / `2` 读取、解析、依赖或前置异常 |
| 留痕 | 自动写 `docs/孙测测/traces/<检查项>-<YYYYMMDD-HHMMSS>.md`，只增不改；`--out /tmp/xxx.md` 可改到临时目录做试跑 |
| 副本规则 | 本目录 `scripts/*.py` 是 `docs/孙测测/scripts/` 的**只读副本**；目录层级同为 `docs/<目录>/scripts/`，所以项目根推导、留痕目录、master 路径全部一致，**副本可直接运行**。改脚本去编辑源改，再 `petctl.py sync` |
| 一致性 | `petctl.py doctor` 逐项比对副本与原件 sha256，漂移即判红 |

### SCR-019 · `comfyui_pet_action_series.py`（**ComfyUI 生图**：1000 帧批量生产线）

| 项 | 内容 |
| --- | --- |
| 作用 | 从 master 按 `manifest.poses[]` 逐动作生产 1000 帧：`prepare` → `keys`（Qwen-Image-Edit 2509 + Lightning-4steps + Multiple-angles，**朝向门禁**）→ `interpolate`（MiniMax H3 FL2VA 56 帧）→ **`frames`（完全离线，只读本地 `videos/*.webp`）**：逐帧四角自适应色键 → `cutouts/` PNG 缓存（6 进程并行）→ 投影去噪 `tight_box` → **v1.3.2 并集安全框 + 全局目标身高纯缩放/平移（不裁人物）** → `180×297` → `encode`（交 SCR-011 整套重编码） |
| `--phase frames` | **零 ComfyUI 调用、零额度**；复用 `cutouts/` 缓存时分钟级。调人物尺寸 / 留白 / 画布只跑这一步，不要重生成 |
| 参数 | `--phase prepare\|keys\|interpolate\|frames\|encode\|all`、`--action NAME`（可重复）、`--length`（默认 56）、`--frames`（默认 50）、`--force`、`--recut`（忽略抠图缓存，从原始视频重新抠图，仍离线）、`--out PATH` |
| 环境变量 | `SUGT_PET_WORK`（工作目录，含 `state.json` / `keys/` / `videos/` / `cutouts/` / `source/` / `su-master.png`）、`SUGT_PET_CANVAS=640x768`、`SUGT_PET_H3_STEPS=4`（**脚本默认 8，定版实测用 4，必须显式设**）、`SUGT_PET_EDIT_STEPS=4`、`SUGT_COMFYUI_BASE`（仅 keys/interpolate 用） |
| 硬编码输入 | `docs/孙测测/traces/assets/su-cel-good-fixed.png`（SCR-017 修补版）；换 master 要覆盖这个路径 |
| 朝向门禁 | `orientation_score()`：白色鞋袜质心 − 肤色脸/手质心 > 0.08 且白质心 > 0.38；`guarded_edit()` 失败换 seed 重试一次，仍失败即中断，拒绝进入补间 |
| 断点续跑 | `state.json` 记录每阶段产物；`--phase all` 可反复执行，`--force` 忽略断点 |
| 留痕 | `traces/精灵动作序列生产-<ts>.md`（记录画布、steps、朝向门禁、归一化实测 `state.normalise`、各动作耗时） |
| 定版战绩 | 20 动作关键姿态 20/20 朝向通过；`512×768` / 4 steps 约 150–203 s/段；v1.3.2 离线重建 1000 帧实测 `h_ref=186.6px` / 最小四边留白 `14px` / 极差 `1.6%`；**v1.3.3 现行**：只重生成 `wake`（`640×768`）、全量重算后 `h_ref=176.0px` / 最小留白 `13px` / 极差 `1.1%` / 框外实体 `0.000%` |
| 三条硬门禁 | 最小四边留白 ≥6px、跨动作人物高度极差 ≤8%、**并集框外实体像素 ≤2%**（防止裁掉动作中的肢体）；不达标直接抛错，不进重编码 |
| 红线 | 唯一真相源是 manifest；**`do_frames()` 里绝不对人物像素用 `frame.crop()`**；所有动作共用脚底同线 + 水平居中锚点；色数与画布从 manifest 读，不写第二份 |

**示例**

```bash
export SUGT_PET_WORK=/tmp/sugt-pet-actions-v13
export SUGT_PET_CANVAS=640x768 SUGT_PET_H3_STEPS=4 SUGT_PET_EDIT_STEPS=4
P=/usr/local/bin/python3.13
$P scripts/petctl.py produce --phase all                         # 全量 1000 帧
$P scripts/petctl.py produce --phase keys --action lifted       # 单动作关键姿态
$P scripts/petctl.py produce --phase frames                     # 全量重新归一化（别加 --action）
$P scripts/petctl.py produce --phase frames --recut             # 视频被替换过才用：重新抠图，仍离线
```

> **`--phase frames` 必须全量**：只算一个动作的坐标系会让切换动作跳位。
> **尺寸类问题不要重生成**：原始视频 + `cutouts/` 缓存足够，改 `manifest.baseSize` 或 `do_frames()` 的 `safe_x/safe_y` 后重跑 `--phase frames` + `--phase encode` 即可。
