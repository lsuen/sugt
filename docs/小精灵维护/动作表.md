## 二、优先级分层与触发规则

```
100 / 99   lifted / landing              拖拽三段（最高，压过一切网关态）
 80 ~ 47   交互 + 自动 + 闲置差分        celebrate … walk
 30 ~ 26   网关状态类                    typing / error / done / sleep / offline
  0        idle                          兜底
```

| 规则 | 说明 |
| --- | --- |
| 查表方式 | `petState.ts` 的 `PET_ACTION_TABLE = PET_ACTIONS.map(...)`，按 priority 降序 `.find()`；生成器已排好序 |
| `trigger: always` | **只给状态类**，匹配 `states` 里的网关态 |
| 其余 `trigger` | 必须**等于动作名**，由布尔 flag 驱动（`dragging → lifted`、`landing`、`petted`、`poked` …） |
| `states: null` / 缺省 | 不限状态（`lifted` / `landing` 就是这样，才能压过 typing / error） |
| `playback: once` | 一次性动作（`landing` / `wake` / `welcome` / `greeting` / `stretch` / `lookAround`），播完回基态 |
| `playback: loop` | 循环动作 |
| 唯一性 | `semantic` / `priority` / `poster` / `loop` / `trigger` 全表唯一（C36 逐项校验） |
| `posePriority[]` | 必须与上表降序完全一致，否则 C36 判红 |

> **历史坑**：曾经 state 类 priority 86–90 高于交互类，`celebrate` 被 `done` 吞掉。改优先级后务必跑 `npm test`（`pet-state-smoke` 有 `done celebrate` 断言）。

## 三、逐动作四边留白实测（**显示不全**的直接证据）

对 20 个 loop 的 **全部 50 帧**逐帧扫描 alpha 包围盒，取每边最小留白（像素，画布 `160×297`）：

| 动作 | 上 / 右 / 下 / 左 最小留白 | 判定 |
| --- | --- | --- |
| `lifted` | 13 / 15 / 46 / 8 | 正常 |
| `landing` | 13 / 0 / 19 / 0 | **贴边** |
| `typing` | 31 / 0 / 23 / 0 | **贴边** |
| `error` | 13 / 0 / 9 / 0 | **贴边** |
| `done` | 16 / 1 / 10 / 0 | **贴边** |
| `sleep` | 17 / 0 / 12 / 0 | **贴边** |
| `offline` | 25 / 5 / 18 / 5 | **贴边** |
| `celebrate` | 24 / 0 / 53 / 0 | **贴边** |
| `disappointed` | 20 / 0 / 16 / 4 | **贴边** |
| `petted` | 17 / 0 / 9 / 1 | **贴边** |
| `poked` | 13 / 0 / 9 / 0 | **贴边** |
| `wake` | 30 / 0 / 16 / 0 | **贴边** |
| `welcome` | 17 / 0 / 13 / 0 | **贴边** |
| `greeting` | 13 / 7 / 9 / 4 | **贴边** |
| `wait` | 15 / 0 / 9 / 0 | **贴边** |
| `stretch` | 13 / 0 / 16 / 0 | **贴边** |
| `lookAround` | 13 / 0 / 9 / 0 | **贴边** |
| `peek` | 22 / 0 / 17 / 0 | **贴边** |
| `walk` | 13 / 2 / 16 / 7 | **贴边** |
| `idle` | 20 / 6 / 16 / 8 | 正常 |

**结论**：17 / 20 个动作至少有一边 0 px，右侧 `R0` 最普遍。加上 `background-position: right bottom`、窗口 `contain` 高度主导（上下 0 余量）、CSS 活感层外推、`overflow: hidden`，就会切掉发梢 / 手 / 鞋。
完整根因与三种修法见《更新维护手册》第四节。

**新增动作七步**（详见《更新维护手册》6.2）：

1. 上面这条追加到 `poses[]`。
2. 改 `actionRegistry.frameBudget.total`（每动作 +50）与 `posePriority[]`（按降序插）。
3. `motion` 只能用合法值：`breathe / bob / float / tilt / wiggle / shake / wave / hop / dangle / settle / droop / nod / turn / stretch`。
4. 两张专属 WebP 放进 `src/assets/pet/`，命名 `su-<name>.webp` / `su-<name>-loop.webp`（注意 `lookAround` 这类驼峰名，CSS 与预览页正则已兼容大写）。
5. 想自动播就加进 `autoActions.idleVariant.poses`；想交互触发才需在 `petActionFlags()` / `usePetBehaviors.ts` 写 flag。
6. `build_pet_preview.py` 的 `STATES` / `ACTIONS` 演示清单补一条（**这是少数要改代码的地方**）。
7. `petctl.py gen` → `petctl.py preview` → `petctl.py all`；确认 C36 / D08 全绿。

> 前端状态机 `petState.ts`、`PetStage.tsx`、`pet.css` 生成段**零改动**——这是 v1.3 注册表设计的全部意义。

## 六、素材命名与映射

| 类型 | 命名 | 帧数 | 用途 |
| --- | --- | --- | --- |
| 静态海报 | `su-<name>.webp` | 1 | 减少动效 / 隐藏窗口 / 静态降级时显示 |
| 动画循环 | `su-<name>-loop.webp` | 50 | 正常播放；`frameOrder` 为 `0..49` 无重复排列 |
| 附加眨眼帧 | `su-blink.webp` | 1 | 随机眨眼；取 sleep 序列第 **25** 帧，与 `su-sleep.webp`（第 0 帧）**字节必须不同** |

**为什么 blink 不能与 sleep poster 同图**：Vite / Rollup 按内容哈希去重，两个 URL 指向同一文件 → dist 只有 40 张 WebP → 契约门禁 D04 判红（历史上真实发生过）。
