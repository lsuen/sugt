## 二、优先级分层与触发规则

```
100 / 99   lifted / landing              拖拽三段（最高，压过一切网关态）
 80 ~ 43   交互 + 自动 + 闲置差分        celebrate … walk / squatDraw / wiggleDance / kickflip / miniGame
 30 ~ 26   网关状态类                    typing / error / done / sleep / offline
  0        idle                          兜底
```

> v1.4 新增 4 个闲置动作 `squatDraw`(46) / `wiggleDance`(45) / `kickflip`(44) / `miniGame`(43) 落在 47 与 30 之间，全部 `group=idleVariant` / `playback=loop` / `states=['idle']`；`posePriority` 扩到 24 条并按降序插入。

| 规则 | 说明 |
| --- | --- |
| 查表方式 | `petState.ts` 的 `PET_ACTION_TABLE = PET_ACTIONS.map(...)`，按 priority 降序 `.find()`；生成器已排好序 |
| `trigger: always` | **只给状态类**，匹配 `states` 里的网关态 |
| 其余 `trigger` | 必须**等于动作名**，由布尔 flag 驱动（`dragging → lifted`、`landing`、`petted`、`poked` …） |
| `states: null` / 缺省 | 不限状态（`lifted` / `landing` 就是这样，才能压过 typing / error） |
| `playback: once` | 一次性动作（`landing` / `wake` / `welcome` / `greeting` / `stretch` / `lookAround`），播完回基态 |
| `playback: loop` | 循环动作 |
| 唯一性 | `semantic` / `priority` / `poster` / `loop` / `trigger` 全表唯一（C36 逐项校验） |
| `posePriority[]` | v1.4 为 **24 条**，必须与上表降序完全一致，否则 C36 判红 |

> **历史坑**：曾经 state 类 priority 86–90 高于交互类，`celebrate` 被 `done` 吞掉。改优先级后务必跑 `npm test`（`pet-state-smoke` 有 `done celebrate` 断言）。

## 四、自动节奏槽位 → 动作映射（`manifest.autoActions`）

| 槽位 | 指向动作 | 参数 |
| --- | --- | --- |
| `idleVariant.poses` | **8 条**（v1.4）：`stretch` / `lookAround` / `peek` / `walk` / `squatDraw` / `wiggleDance` / `kickflip` / `miniGame` | 12000–30000 ms 触发；`holdCycles 1 + tailMs 120`，毫秒由所选姿势的素材时长派生（3924–5018 ms），不再写死 2200 |
| `welcome` | `welcome` | `holdCycles 1 + tailMs 1200`（≈5590 ms） |
| `celebrate` | `celebrate` | `holdCycles 1 + tailMs 200`（≈4995 ms） |
| `disappointed` | `disappointed` | `holdCycles 1 + tailMs 0`（4795 ms） |
| `wake` | `wake` | `holdCycles 1 + tailMs 0`（4390 ms） |
| `wait` | `wait` | 等待批准态驱动 |
| `drag` | `pose: lifted` + `releasePose: landing` | `holdCycles 1 + tailMs 0`（落地完整一遍 4390 ms） |
| `bursts.done` / `bursts.error` | 结果态保持时长（代码未消费，以 `resultHoldMs()` 为准） | 3500 / 6000 ms（历史值） |
| `interaction` | 交互冷却 1200 ms；减少动效时降级 `poster` | — |
| `blink` / `facing` / `wander` | 不指向动作，是独立节奏器 | 3000–9000 / 10000–25000 / 18000–40000 ms |

> **时长口径（v1.5）**：`holdCycles` / `tailMs` 只声明「播几遍 + 尾部停留」，毫秒由 `poseHoldMs()` 按 `PET_FRAME_MS` 求和派生；`resultHoldMs('error')` = error 一遍 + disappointed 一遍（9590 ms）。历史 `holdMs` 固定值会让动作播到一半就被切回，详见 `AGENTS.md`「Pet action duration」。

## 六、素材命名与映射

| 类型 | 命名 | 帧数 | 用途 |
| --- | --- | --- | --- |
| 静态海报 | `su-<name>.webp` | 1 | 减少动效 / 隐藏窗口 / 静态降级时显示 |
| 动画循环 | `su-<name>-loop.webp` | 50 | 正常播放；`frameOrder` 为 `0..49` 无重复排列 |
| 附加眨眼帧 | `su-blink.webp` | 1 | 随机眨眼；取 sleep 序列第 **25** 帧，与 `su-sleep.webp`（第 0 帧）**字节必须不同** |

**为什么 blink 不能与 sleep poster 同图**：Vite / Rollup 按内容哈希去重，两个 URL 指向同一文件 → dist 只有 40 张 WebP（**v1.3.3 历史真实发生值**；若 v1.4 的 49 张发生同类去重则为 48 张，属推演）→ 契约门禁 D04 判红。v1.4 现行实测 dist **49 张 / 5536.62 KB**、`check_pet_overlay.py` **84/84**（含 D04）通过，未发生去重。
