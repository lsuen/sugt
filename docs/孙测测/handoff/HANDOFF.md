## 四、修复后的复验对接规则

1. 开发反馈修复完成 → **不直接放行**，先按原复现步骤逐条复验首轮缺陷，记录「已修复 / 未修复 / 引入新问题」，并做前后证据对比。
2. 同步执行**上线前回归测试**：受影响模块 + 关联链路 + 全量既有自动化套件，确认无回归。
3. 两项均通过才出具 `测试报告02.md` 与放行结论；任一未通过 → 回到「不能上线」，编号 `03` 递增。
4. 复验与回归的每一条结论都必须落到 `traces/` 留痕，报告只引用「留痕文件名 + 结论」。

## 五、约定

- 对接结论一律中文，问题先行、背景后置。
- 「已确认」与「待验证推断」分开列，推断不得充当放行或拦截的唯一依据。
- 检查阶段默认**只报告、不改产品代码**；修复由开发执行，我负责复验与回归。
- 版本号 / 构建号必须与 `reports/` 中报告头双向可追溯，不确定时标为待确认项，不猜测。
