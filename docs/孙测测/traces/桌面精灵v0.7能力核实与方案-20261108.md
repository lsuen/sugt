## 二、方案（v0.7）

1. **抠图改链路，不再做白底泛洪**：Qwen-Edit 一次把参考底改成纯净洋红底，再以它为参考重出全部状态帧；用**确定性色键**（色度空间距离 → 软 alpha → 去溢色反预乘）在落包脚本里直出 RGBA。发丝缝隙是纯背景色，与连通性无关，必然 α=0；白鞋白袜、眼白、外套高光都不参与背景判据，不会被打洞。
2. **真人级动画，不做图片叠加**：每个状态由若干真实差异帧组成，用 ComfyUI `SaveAnimatedWEBP` 编码成**带 alpha 的动画 WebP**（CAP-01 已验证）；CSS 只负责连续缓动的呼吸/倾斜，离散细节动作由动画帧承担。
3. **交互打磨**：鼠标靠近 → 视线/头部跟随（3D 倾斜 + 眼神高光位移）与靠近光晕；随机眨眼；点击弹跳与轻声回应；拖拽抬起/倾斜/落地回弹；地面投影随状态；状态之间交叉淡入；隐藏窗口 / reduced-motion 自动切静态帧。
4. **不需要改白头发**：CAP-05 的纯色底 + 色键已能根治发丝缝隙，白毛是兜底方案，本轮不启用，保持既定雾蓝短发设定。

## 三、排除项（怀疑过但核实不成立）

- 怀疑 BiRefNet / RMBG 能一键软边抠图 → 权重缺失（CAP-04），且下载权重需写入远端 `models/` 目录，本机 API 无该能力，判为不可行。
- 怀疑 `Qwen-Image-Layered` 能直出分层 RGBA → 本机只有 `EmptyQwenImageLayeredLatentImage`，`UNETLoader` 14 个权重里无 layered 模型，链路不完整。
- 怀疑 `BriaRemoveImageBackground` 可用 → 是 `api_node`（云端计费），与「零额度、只用本地算力」红线冲突，排除。
- 怀疑 `Image Remove Background (Alpha)` 亮度阈值法可替代 → 角色含米白外套 / 白袜 / 白鞋 / 眼白，会把角色内部一起清掉，排除。
- 怀疑 MiniMaxH3 视频可直接出透明通道 → 视频 VAE 输出 RGB，`BriaTransparentVideoBackground` 同样是云端 API 节点，排除；视频只留作宣传素材。
- 怀疑动画 WebP 的 alpha 在浏览器会丢 → 产物 `VP8X` alpha 位 + `ANMF` 均存在，Chromium / WebKit 均支持带 alpha 的动画 WebP（**待验证推断**：Windows WebView2 / macOS WKWebView 真机未实测）。

## 四、风险与边界

- 动画 WebP 帧数直接决定包体积，需要实测并设上限（目标 ≤ 1.5 MB，当前 5 帧 85.45 KB）。
- ComfyUI `SaveAnimatedWEBP` 会写入 EXIF，`ffprobe` 报 `invalid TIFF header in EXIF data`（不影响解码）；落包前用 `webpmux -strip exif` 清掉。
- Qwen-Edit 各帧构图漂移仍需按 alpha bbox 统一对齐（沿用 v0.5 已验证做法）。
- 本轮为迭代验收，Windows / macOS 双平台拖动与穿透组合仍未真机实测，不构成上线放行结论。
