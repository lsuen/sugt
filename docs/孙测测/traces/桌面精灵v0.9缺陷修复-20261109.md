## 二、缺陷明细

### PET-V09-01 · 五个交互 / 表情动作出现双重影像

| 字段 | 内容 |
| --- | --- |
| 问题 | `.pet-loop` / `.pet-poster` 的 wave / peek / shy / celebrate / walk 规则写成两个 `background-image`，作者注释误以为「素材未落包时回退到近义态」 |
| 复现步骤 | 打开精灵 → 轻碰（wave）或靠近（peek/walk）、完成（celebrate），或预览页切到对应状态 |
| 预期结果 | 每个动作只显示一层立绘，透明区域直接露出桌面 |
| 实际结果（已确认） | `src/overlay.css:399-413` 修复前每个动作挂两张图，例如 wave = `su-wave-loop.webp` + `su-done-loop.webp`；`.pet-loop/.pet-poster` 共用 `background-size: contain`、`background-position: right bottom`（:381-389），两层完全重叠。动画 WebP 前景占比约 16–17%，其余为 alpha=0，下层 done/idle 动画会从透明区透出并同步播放 |
| 导致的现象 | 轻碰招手、靠近倾听、害羞、庆祝、走近五种动作都是「两个小人叠在一起 / 闪烁重影」；静态帧降级时同样重影。影响全部 v0.8/v0.9 新增动作，旧五态正常 |
| 根因 | CSS 多值 `background-image` 是**分层叠加**，不是加载失败时的 fallback；加载成功也不会取消下层 |
| 修复后的结果 | 10 条规则各只保留对应素材单层背景（`src/overlay.css:399-413`）；契约新增 C17 逐个解析十条规则，断言 urls 恰为单元素且素材已落包，防回归 |
| 优先级 / 严重级别 | P1 / 一般 Major |
| 问题类型 / 定位 | 前端 UI · `src/overlay.css:399-413` |
| 状态 | **已修复**（契约 C17 + 预览页十状态可人工复核） |

### PET-V09-02 · 视线轮询在配置切换 / 窗口隐藏后仍继续

| 字段 | 内容 |
| --- | --- |
| 问题 | `pollGlobal()` 的 `.finally()` 无条件重排 50ms 定时器，未按 effect 生命周期取消 |
| 复现步骤 | 设置 → 桌面精灵 → 关闭「视线跟随」；或反复开关该开关；或最小化 / 隐藏悬浮窗 |
| 预期结果 | 关闭后立即停止 `pet_global_cursor` + `scaleFactor` 轮询；隐藏时不做无效 IPC |
| 实际结果（已确认） | 修复前 `src/overlay.tsx:264-283` 的 `.finally(() => { pollTimer = setTimeout(pollGlobal, 50); })` 不检查 cleanup；已在飞行的 Promise 会重新拉起一条链，切换开关会叠加多条并行链（约 20 次/秒 × 2 IPC） |
| 导致的现象 | 关掉视线开关后仍持续空转 IPC；高频轮询不吃 CPU 但持续唤醒 WebView；多次切换后重复写 `--gaze-*` |
| 根因 | 定时器链缺少 `cancelled` 守卫 |
| 修复后的结果 | 新增 `cancelled` 与 `schedulePoll()`；cleanup 先置位；`.then` / `.finally` / 跳过分支均检查；`document.hidden` 或刚有本地指针事件时跳过本轮 IPC。契约 C15 增加 `let cancelled = false` / `document.hidden` 断言 |
| 优先级 / 严重级别 | P2 / 一般 Major |
| 状态 | **已修复** |

### PET-V09-03 · 眨眼计时器数组无界增长

| 字段 | 内容 |
| --- | --- |
| 问题 | `later()` 只 push timer id，执行后不移除 |
| 复现步骤 | 精灵长时间运行且请求状态频繁切换（typing/done/idle 交替） |
| 预期结果 | 计时器集合只保留尚未触发的 id |
| 实际结果（已确认） | 修复前 `src/overlay.tsx:328-330` 每次 `schedule()` 都 push；眨眼 effect 以 `petState` 为依赖，每次状态变化 cleanup 会遍历整个历史数组 |
| 导致的现象 | 长时间运行后数组持续变大，cleanup 遍历线性变慢；属内存 / 调度泄漏，不影响立绘正确性 |
| 根因 | 缺少执行后自移除 |
| 修复后的结果 | 定时器回调先 `filter` 掉自身 id 再执行 `fn()` |
| 优先级 / 严重级别 | P3 / 轻微 Minor |
| 状态 | **已修复** |

## 三、排除项（怀疑过但核实不成立）

- **素材本身坏帧 / 缺 alpha**：逐个解析 21 个 WebP 的 RIFF，10 个动画均为 `ANIM + 6×ANMF + alpha 标志位置位`；双影与素材无关。
- **ACL 漏放 `pet_global_cursor`**：`app-commands.toml` 的 `allow-overlay-commands` 已含该命令，`app.rs` 已注册，`capabilities/overlay.json` 引用该权限，链路通。
- **互动模式没解除鼠标穿透**：`overlay.rs::apply()` 按 `pet_interactive || pet_always_interactive || edit` 设置 `set_ignore_cursor_events(!interactive)`，逻辑正确。
- **三档尺寸被后端拒绝**：`set_overlay_config` 校验 `120~800 / 40~420`，新三档 148×168、180×204、220×250 均在范围内（C10 动态断言）。
- **ENV-001 是网关功能回归**：本轮未改任何 Rust 产品代码；绕过代理立即通过，排除代码回归。

## 五、遗留风险与待验证推断

1. **原生窗口组合未双平台实测**：带 alpha 动画 WebP 在 Windows WebView2 / macOS WKWebView 的逐帧解码、拖动后 `click` 误触仍需真机核对；本报告不构成上线放行。
2. **窗口级矩形穿透**：互动模式解除穿透后 OS 仍按整个窗口矩形拦截点击（含左侧透明通知栏），CSS 只缩小 React 热区；属已知架构限制。
3. **包体积**：精灵素材 404 KB → 807.62 KB（+403 KB），zip 对已压缩 WebP 收益极小，需打版时确认安装包增量。
4. **用户现场现象待确认**：本轮按代码证据修复上述缺陷；若真机上另有具体现象（状态/气泡/设置/窗口拖动等），需补充复现步骤后单独定位。
