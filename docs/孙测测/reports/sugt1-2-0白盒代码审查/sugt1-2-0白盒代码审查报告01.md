## 三、P1 缺陷详情

### BE-01｜skill_id 未校验直接拼路径，可越界删除/打开任意目录
1. 标题：skill_id 未做白名单校验即用于构造文件路径并删除。
2. 触发：调用 `store_uninstall_skill({skill_id:"../../../Users/xxx"})`，或 `store_open_skill(staged:true, 恶意 skill_id)`。前提：webview 侧可发起任意 IPC（XSS 或被篡改前端）。
3. 预期：uninstall/remove/resolve 前校验 skill_id 属于已安装项且为单一合法路径段，拒绝含 `..`/分隔符的 id。
4. 实际（已确认）：`store/install.rs:66-70` `staged.skills.remove(skill_id)` 删除前未 `contains_key` 校验，直接 `remove_dir_if_exists(&store_paths.staged_skill_dir(skill_id))`；`store/paths.rs:40-42` `self.skills_dir.join(skill_id)` 无净化；暴露面 `store/commands.rs:252-257`、`:371-387`。
5. 现象：可删除 config_dir 之外任意目录、以编辑器打开任意路径；影响本机文件系统完整性。
6. 根因：`store/install.rs:66`、`store/paths.rs:41` 缺少 id 白名单/规范化校验。
7. 修复后结果：越界 id 被拒绝，合法 id 正常卸载。验收：`cargo test -p sugt` 增加「越界 id 不删除 skills_dir 外文件」用例。
8. 优先级 P1；级别 Critical。9. 状态：已修复。
修复说明：`store/paths.rs` 新增 `validate_skill_id`（单一 Normal 路径段；拒绝空、`.`/`..`、`/`、`\`、`:`、NUL/控制字符、绝对路径）；`store/install.rs` 的 `install_skill` / `uninstall_skill` / `mount_skill` / `unmount_skill` / `resolve_skill_path`（含 `store_open_skill`）入口先校验，越界一律 Err，合法 id 行为不变。新增单测：`paths::validate_skill_id_accepts_legit_and_rejects_traversal`、`install::uninstall_rejects_traversal_ids_and_keeps_outside_files`、`uninstall_legit_id_still_removes_staged_dir`、`resolve_mount_unmount_reject_bad_ids`。

### BE-02｜更新包 asset_name 来自远端且未净化：路径穿越写文件 + PowerShell 注入
1. 标题：远端 release asset 名称未净化即拼路径与 shell 命令。
2. 触发：更新接口返回 asset 名称含 `../` 或单引号（如 `x';calc;'.zip`），用户点更新。
3. 预期：asset_name 规约为单一文件名，拼进 shell 时安全转义。
4. 实际（已确认）：`update/mod.rs:211` `asset_name: asset.map(|a| a.name.clone())` → `:266-269` 未净化 → `:329` `staging.join(asset_name); std::fs::write(...)` 可写到 staging 之外 → `:541-551` PowerShell `-Command "...-LiteralPath '{zip_path}'..."` 单引号未转义即注入。
5. 现象：可覆盖应用配置/可执行文件；Windows 上以当前用户权限执行任意命令。
6. 根因：`update/mod.rs:266-269`、`:329`、`:545-546`。
7. 修复后结果：asset_name 经 `Path::file_name()` + 字符白名单；PowerShell 参数数组传递 + 单引号翻倍转义。验收：净化单测 + Windows 手工注入用例。
8. 优先级 P1；级别 Critical。9. 状态：已修复。
修复说明：`update/mod.rs` 新增 `sanitize_file_component`（单一文件名 + 字符白名单 `[A-Za-z0-9._+-]`，拒绝 `..`/分隔符/引号/空格/前导点）与 `safe_package_path`（canonicalize staging 后断言落点仍在其内，拒绝符号链接目标）；`download_and_apply` 对 `asset_name` 与 `latest_version`（staging 目录名）均先净化。Windows 解压改为常量 `-Command` + 环境变量 `SUGT_UPDATE_ZIP/SUGT_UPDATE_DEST` 传路径，不再字符串插值（比单引号翻倍更彻底）。新增单测：`asset_name_sanitizer_rejects_traversal_and_injection`、`safe_package_path_stays_inside_staging`、`safe_package_path_rejects_symlink_target`（unix）。Windows 真机注入用例待手工验证。

### ARCH-01｜Agent 客户端元数据双份维护
1. 标题：客户端 name/vendor/protocol/launch_command 在 fingerprints() 与 ADAPTERS 两处维护。
2. 触发：「发现 Agent」弹窗输入 ≥2 字符查询，与空查询目录视图对比。
3. 预期：单一真相源，任何入口显示一致。
4. 实际（已确认）：`agent_discover.rs:47-171` `fingerprints()` 自带完整元数据；`:514-527` `probe_fingerprint` 用 `fp.name/vendor/protocol/launch_command/clear_vars`；`:175-191` `known_agents()` 从 `agent_adapters::all()` 派生，`:266-284` 用 `adapter.*`；真相源 `agent_adapters.rs:88-378 ADAPTERS`。
5. 现象：改客户端名/协议/启动命令须同步两处，漏改导致搜索结果与目录视图不一致，launch_command 漂移会启动错误 CLI。
6. 根因：`agent_discover.rs:47 fingerprints()` 承担超出 env 模板的元数据职责。
7. 修复后结果：fingerprints 退化为纯探测规则表，展示字段统一从 `agent_adapters::by_id(fp.id)` 取。验收：对每个 id，两路径返回字段一致的断言测试。
8. 优先级 P1；级别 Major。9. 状态：已确认。

### FE-01｜快速对话会话每 3 秒被后台轮询重置
1. 标题：QuickChatModal 历史加载 effect 依赖不稳定的 providers 引用。
2. 触发：打开快速对话弹窗，发消息后停留 10 秒（dashboard 3 秒轮询持续）。
3. 预期：历史仅弹窗打开时加载一次，后台刷新不改聊天视图。
4. 实际（已确认）：`main.tsx:893` 每次渲染构造新 providers 数组；`:540` 3 秒 `refresh()` → `setProviders` 换引用；`GatewayAccessBanner.tsx:305` 原样透传；`QuickChatModal.tsx:144` `}, [open, activeProviderId, providers]` 含数组依赖；`:117/:122` 重跑时 `setLoadingHistory(true)` + `setMessages(后端快照)` 整体覆盖。
5. 现象：每 3 秒闪「加载中」、消息列表被重置；未 persist 完的消息短暂消失。影响所有快速对话用户，持续可复现。
6. 根因：`QuickChatModal.tsx:144` 依赖引用不稳定的数组 props。
7. 修复后结果：effect 依赖收缩为 `[open]`，用 ref 保存最新 providers；或 main 用 useMemo 缓存。验收：停留 15s 无闪烁、消息不消失；单测断言 `get_quick_chat_history` 仅调用 1 次。
8. 优先级 P1；级别 Major。9. 状态：已修复。
修复说明：`src/QuickChatModal.tsx` 历史加载 effect 依赖收缩为 `[open]`，providers / activeProviderId 通过 ref 读取最新值，初始选择逻辑不变；另加一个只调用 `setProviderId` 的补选 effect（providers 迟到或当前选择失效时补选，不触碰 messages / loadingHistory）。验证方式：打开弹窗发消息后停留 15s，应无「加载中」闪烁、消息不丢；`get_quick_chat_history` 每次打开仅调用 1 次。仓库无组件级前端测试脚手架，未新增脚本。
