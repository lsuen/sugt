## 一、目录与文件命名

| 对象 | 规则 | 1.1.8 示例 |
| --- | --- | --- |
| 报告目录 | `reports/sugt<主>-<次>-<修>上线评估/`，目录名即声明版本与阶段 | `reports/sugt1-1-8上线评估/` |
| 报告文件 | `sugt<主>-<次>-<修>测试报告NN.md` | `sugt1-1-8测试报告01.md` |
| 编号 NN | `01` 首轮评估 / `02` 修复后复验 + 上线前回归 / `03+` 追加轮次 | — |

**报告只增不改**：任何一轮结论都永久留痕，禁止回写覆盖历史报告；纠正以新编号报告 + 引用旧报告的方式表达。

> ⚠️ **待确认项 CFG-001**：指令示例 `sugt1-8-8测试报告01.md` 与版本 `1.1.8` 字面不一致，本目录默认按 `sugt1-1-8`。确认前不得写入正式报告的版本号字段作为「已确认」结论。

## 二、上线标准（不计成本，不降级）

上线前评估测试**不做抽样替代、不因耗时裁剪**，至少覆盖：

| 维度 | 必做内容 |
| --- | --- |
| 配置管理 | 四处版本号一致（SCR-001）、构建号可追溯、目标平台明确 |
| 功能 / 业务 | 核心链路全量、异常分支、状态流转、数据一致性、升级与回滚路径 |
| 前端 UI | 主题契约与皮肤切换、交互与视觉、响应式、控制台与网络错误 |
| 白盒架构 | 错误传播与失败出口闭合、状态快照与还原、并发与原子写、降级策略 |
| 性能 / 兼容 / 安全 | 目标平台矩阵、资源与耗时基线、凭证与敏感信息、依赖告警 |
| 全量既有套件 | `npm test`、`npm run build`、`cargo test` 全量、真实构建产物验证 |
| 存量用户路径 | 专门构造旧版本遗留态（如 1.1.7 无快照接管态）验证升级，不用本机新态代替 |

首轮评估与修复后回归**都按此标准执行**；回归额外叠加「受影响模块 + 关联链路」的定向覆盖。

## 三、报告骨架（CMMI3 以上）

```
# sugt<版本>测试报告NN — <首轮评估 / 复验与回归>

## 1. 报告头
报告编号 / 被测版本 / 构建号 / 目标平台 / 测试环境 / 测试范围 /
执行时间 / 执行人（孙测测）/ 关联留痕与对接单编号

## 2. 测试概要与统计
用例总数 / 通过 / 失败 / 阻塞 / 通过率；按维度列出执行项与结论；
命令与脚本清单（含退出码）

## 3. 缺陷明细（每条 10 字段固定集）
DEF-NNN 标题 → 复现步骤 → 预期结果 → 实际结果（带证据）→ 现象与影响范围 →
根因 → 修复后结果与验收方式 → 问题类型 → 问题定位 → 优先级 → 严重级别 → 状态

## 4. 缺陷分布与证据分级
按类型 / 模块 / 严重度统计；「已确认」与「待验证推断」分列；排除项说明

## 5. 复验与回归（02 及以后轮次必填）
首轮缺陷逐条复验结果（前后证据对比）、回归范围与结果、是否引入新问题

## 6. 遗留风险
已知留白 / 未覆盖场景 / 环境限制 / 待确认项（如 CFG-001）

## 7. 放行结论
□ 可以上线　□ 不能上线
不能上线时逐条对应阻断项并给证据、解除条件与下一轮编号

## 8. 附件与证据清单
留痕文件、日志片段、命令输出、构建产物信息
```

顺序铁律：**先说问题、现象、修完会怎样，再谈背景**；证据必须带文件:行号或命令输出；根因未定位写「根因待查」，不猜。

## 四、放行判定规则

| 情形 | 结论 |
| --- | --- |
| 存在 P0 / Blocker，或影响上线的 Critical 缺陷 | **不能上线** |
| 核心链路失败、数据丢失、升级路径无法干净退出 | **不能上线** |
| 全量套件未跑完 / 目标平台未构建验证 / 版本构建号无法追溯 | **不能上线**（证据不足，不放行） |
| 仅 P2/P3 且已有明确规避措施与排期，汇总层记录遗留风险 | 可放行，但必须写明风险与责任人 |
| 修复后复验未逐条通过，或回归发现新问题 | **不能上线**，编号递增再测 |

**「不能上线」是硬结论**：不因进度、耗时或「大概率没问题」而软化；解除条件只能是「开发修复 → 缺陷复验通过 → 上线前回归通过 → 新编号报告放行」。

## 五、产出后动作

1. 报告写入本目录对应版本子目录。
2. 在 `MAP.md` 的「关联版本报告」列登记，形成报告 ↔ 脚本 ↔ 留痕双向可查。
3. 在 `handoff/HANDOFF.md` 追加对接记录；「不能上线」时同步输出缺陷对接单。
4. 所有引用证据指向 `traces/` 留痕文件名，不把大段日志贴进报告。
