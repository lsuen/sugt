## 3. 核心模块详解

### 3.1 网关代理模块（gateway.rs）

项目最核心文件（~995 行），实现嵌入式 HTTP 反向代理服务器。

**路由表**：

```
GET  /health           → 健康检查
GET  /v1/models        → 列出可用模型
POST /v1/messages      → Anthropic 协议代理
ANY  /*path            → OpenAI 兼容协议代理（兜底）
```

**请求转发流程**：

1. 客户端发送 HTTP 请求到 `127.0.0.1:8787`
2. Axum 路由匹配分发路径
3. 从 `AppConfig` 中获取当前活跃 Provider（启用的默认模型）
4. 重写请求体中的 `model` 为目标模型名
5. 注入 API Key（Bearer token 或 x-api-key）
6. 转发到上游 Base URL，拼接正确路径
7. 流式响应逐块转发（实时统计 token 用量）
8. 成功时记录统计信息，失败时触发故障转移

**故障转移实现**：

```
ordered_providers() 排序：活跃 Provider 优先 → 其他启用 Provider
遍历 Provider 列表：
  └─ 遇到 <500 错误或成功 → 直接返回
  └─ 其他错误 → 继续尝试下一个
  └─ 受 failover_enabled 开关控制
```

**CORS 策略**：使用 `tower-http::CorsLayer::permissive()` 允许所有来源。

### 3.2 协议适配模块（anthropic_adapter.rs）

技术亮点之一（~887 行 + 单元测试），支持 Anthropic ↔ OpenAI 双向协议实时转换。

**Anthropic → OpenAI 请求转换**（`anthropic_to_openai`）：

| Anthropic 字段 | OpenAI 映射 |
|---------------|-------------|
| system | system role message |
| messages content blocks（text/tool_use/tool_result） | OpenAI 多轮对话格式 |
| tool_use | tool_calls |
| tool_choice | function calling |
| max_tokens / temperature / top_p / stop_sequences | 直接映射 |
| stream=true | 自动添加 stream_options: { include_usage: true } |

**OpenAI → Anthropic 响应转换**（`openai_to_anthropic_response`）：

非流式：将 OpenAI chat.completion JSON 转为 Anthropic messages JSON 结构。

流式 SSE 转换（关键实现）：

```
OpenAI SSE 事件流 → Anthropic SSE 事件流
  chat.completion.chunk → content_block_start → content_block_delta
  → content_block_stop → message_delta → message_stop
```

实现了 `SseLineParser`（SSE 行解析器）和 `AnthropicStreamAdapter`（流式转码器），支持 Tool Call 增量参数拼接。

**Thinking Block 处理**：Anthropic 的 thinking 块转为文本标记，保留在对话上下文中。

### 3.3 模型配置管理（model.rs + commands.rs）

**ProviderConfig 数据结构**：

```rust
pub struct ProviderConfig {
    id: String,              // UUID v4
```

- 通过 `trim_base_url` 去除尾部多余斜杠

### 3.5 客户端接管模块（clients.rs）

通过 Windows 用户环境变量（`setx` / `reg`）接管客户端流量。

**Claude Code 接管**：

| 环境变量 | 值 |
|---------|-----|
| ANTHROPIC_BASE_URL | http://127.0.0.1:8787 |
| ANTHROPIC_AUTH_TOKEN | sugt-local-key |

**Codex 接管**：

| 环境变量 | 值 |
|---------|-----|
| OPENAI_BASE_URL | http://127.0.0.1:8787/v1 |
| OPENAI_API_BASE | http://127.0.0.1:8787/v1 |
| OPENAI_API_KEY | sugt-local-key |

**冲突检测**：自动检测 `ANTHROPIC_API_KEY` 和 `CLAUDE_CODE_API_KEY` 等冲突变量。

**实现方式**：
- `set_user_env`: `setx` 命令写入 HKCU 用户环境变量
- `unset_user_env`: `reg delete HKCU\Environment` 删除
- 同时生成 `.cmd` 启动脚本到配置目录

### 3.7 试用治理模块（trial.rs）

**三种模式**：

| 模式 | 编译期变量 | 行为 |
|------|-----------|------|
| Dev | 无 `SUGT_TRIAL_ENABLED` | 无限制 |
| SelfUse | 有 `SUGT_EDITION` 但 `SUGT_TRIAL_ENABLED != true` | 无限制 |
| Trial | `SUGT_TRIAL_ENABLED = true` | 受控 |

**有效期校验**：
1. 读取编译期注入的 `SUGT_TRIAL_EXPIRES_AT`（ISO 8601）
2. 取当前 UTC 时间比较
3. 过期 → 返回 `TrialStatus::Expired`

**机器绑定**：
1. 生成机器指纹：SHA-256(`COMPUTERNAME | USERDOMAIN | USERNAME | MachineGuid`（注册表）)
2. 状态文件 `trial-state.json` 记录首次运行的 `machine_hash`
3. 检测到 `machine_hash` 不匹配 → 返回 `TrialStatus::MachineMismatch`
4. 检测到系统时间回滚（比 `last_seen_at` 早 10 分钟以上）→ 返回 `TrialStatus::ClockRollback`
5. 跨 `build_id` 构建版本自动重置状态文件

**防护点**：
- `start_gateway` IPC 命令调用 `trial::ensure_allowed()`
- CLI `serve` / `test` / `env install` 命令同样校验
- 托盘菜单"启动网关"按钮受控

### 3.8 CLI 实现（bin/cli.rs）

使用 Clap derive 宏，与 GUI 共享 `sugt_lib` 逻辑库。

**命令树**：

```
sugt-cli
├── init         # --base-url --api-key --model [--name]
├── status       # 查看状态
├── serve        # [--host] [--port]
├── test         # 测试所有 Provider
└── env
    ├── status       # 查看接管状态
    ├── install      # [--start-gateway] 开启接管
    ├── uninstall    # 关闭接管
    ├── repair       # 修复接管
    └── print        # 打印启动脚本
```

**后台启动机制**：`env install --start-gateway` 会在网关未运行时，自动启动隐藏窗口的 `sugt-cli serve` 后台进程，轮询 `/health` 等待就绪（最多 10 秒）。

```

3. npx tauri build --no-bundle（编译 Rust + 嵌入 WebView 资源）
4. cargo build --release --bin sugt-cli（编译 CLI）
5. 组装便携包目录：
   ├── SUGT.exe
   ├── sugt-cli.exe
   ├── SUGT.ico
   ├── README.txt
   ├── VERSION.txt
   └── manifest.json
6. 可选：Compress-Archive 压缩为 ZIP
7. 可选：连通性测试
```

### Claude Code 通过 SUGT 使用 DeepSeek（协议转换场景）

```
Claude Code CLI
  │
  │ POST /v1/messages (Anthropic Messages JSON)
  ▼
SUGT Gateway (axum Router)
  │
  ├── route: "/v1/messages" → proxy_anthropic_messages()
  │
  ├── provider.protocol == Anthropic?
  │   ├── YES → proxy_anthropic_native() 直接转发
  │   └── NO  → proxy_anthropic_via_openai()
  │       ├── anthropic_to_openai(请求体)
  │       │   └── system → system message
  │       │   └── content blocks → OpenAI messages
  │       │   └── tool_use → tool_calls
  │       │   └── stream=true → stream_options
  │       │
  │       ├── reqwest::Client 转发到 DeepSeek API
  │       │   └── POST https://api.deepseek.com/v1/chat/completions
  │       │   └── Authorization: Bearer sk-xxx
  │       │
  │       ├── 流式响应？
  │       │   ├── YES → AnthropicStreamAdapter::adapt()
  │       │   │   └── OpenAI SSE → Anthropic SSE 实时转码
  │       │   └── NO  → openai_to_anthropic_response()
  │       │       └── chat.completion JSON → messages JSON
  │       │
  │       ├── gateway_stats 记录指标
  │       └── 响应返回 Claude Code
  │
  └── 故障转移（如 5xx）
      └── 尝试下一个 ordered_provider
```

## 8. 关键实现细节

### 8.1 SSE 流式转码（核心难点）

Anthropic 的 SSE 事件格式与 OpenAI 不同。SUGT 实现了实时转码，而非等全部响应再转换：

```
OpenAI SSE:
  data: {"choices":[{"delta":{"content":"Hello"}}]}

Anthropic SSE 事件序列：
  event: message_start        → 消息起始
  event: content_block_start  → 内容块起始
  event: content_block_delta  → 内容块增量（多次）
  event: content_block_stop   → 内容块结束
  event: message_delta        → 消息增量
  event: message_stop         → 消息结束
```

`AnthropicStreamAdapter` 内部维护状态机，将 OpenAI 的流式 chunk 映射为正确的 Anthropic 事件序列。

### 8.2 前端 IPC 通信

前端通过 `@tauri-apps/api` 的 `invoke()` 调用 Rust 后端命令。无状态 REST，每次 invoke 都会读取最新的 `AppConfig`。前端使用 `useEffect` + `setInterval` 实现轮询：

- 网关状态轮询：3 秒间隔
- 日志轮询：2 秒间隔
- 流量统计轮询：3 秒间隔

### 8.3 跨构建版本的状态重置

`trial-state.json` 中记录了 `build_id`。启动时检测到当前 `build_id` 与文件中记录的不同，自动重置状态文件（清除机器绑定记录等），允许在新构建版本中重新绑定。
