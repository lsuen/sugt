## 1. 产品概述

SUGT（su gateway）是一款面向内部研发场景的本地大模型网关工具。核心价值是让 Claude Code、Codex（GitHub Copilot Codex）等 AI 编程客户端通过本地代理，无缝访问国内各大 LLM 服务商的大模型 API，无需修改客户端配置。

**一句话定位**：AI 编程客户端的"万能适配器"。

### 1.1 产品形态

| 形态 | 文件 | 说明 |
|------|------|------|
| GUI 桌面应用 | SUGT.exe | Tauri 图形界面，面向普通用户 |
| 命令行工具 | sugt-cli.exe | 无界面环境使用，面向高级用户 |
| 绿色便携包 | 目录发布 | 解压即用，不写注册表（除可选开机启动） |

### 1.2 版本说明

当前版本 v0.2.5 为商店试用版（store-trial），有效期至 2026-07-13。产品有两条产品线：

- **feature（功能版）**：核心网关能力 + 模型管理 + 客户端接管
- **store（商店版）**：功能版全部能力 + 技能商店（Skill 发现/安装/挂载）

每个产品线又有三个授权变体：
- **dev（开发版）**：无有效期限制，仅供开发测试
- **self（自用版）**：无有效期限制
- **trial（试用版）**：30 天有效期 + 机器绑定

## 2. 核心功能模块

### 2.1 本地网关代理

SUGT 在用户本机（默认 127.0.0.1:8787）启动一个 HTTP 网关服务，AI 客户端将请求指向该地址，网关负责转发到真实的上游 LLM API。

**支持的路由**：

| 路径 | 用途 | 说明 |
|------|------|------|
| `GET /health` | 健康检查 | 返回网关运行状态和当前活跃模型 |
| `GET /v1/models` | 模型列表 | 返回所有已启用的模型列表（OpenAI 兼容格式） |
| `POST /v1/chat/completions` | OpenAI 协议代理 | 转发 OpenAI 格式的对话请求 |
| `POST /v1/messages` | Anthropic 协议代理 | 转发 Anthropic Messages 格式请求 |
| 其他路径 | 通用代理 | 其他路径按 OpenAI 协议转发 |

**关键能力**：

- **协议转换**：Anthropic ↔ OpenAI 双向协议自动转换。例如 Claude Code 发送 Anthropic 格式请求，网关可将其转为 OpenAI 格式发送给 DeepSeek，再将响应转回 Anthropic 格式返回给 Claude Code
- **流式响应（SSE）**：支持 Server-Sent Events 流式传输，实时转码
- **故障转移**：配置多个模型 Provider 后，当首选 Provider 返回 5xx 错误时，自动尝试下一个可用 Provider
- **4xx 不重试**：400/401/403/404 等客户端错误不触发故障转移，避免掩盖鉴权问题

### 2.2 模型配置管理

用户可以在 GUI 或 CLI 中管理上游 LLM 服务商的连接配置。

**支持的国内 LLM 服务商（12 家预设）**：

| 服务商 | 标识 | OpenAI 协议 | Anthropic 协议 |
|--------|------|-------------|----------------|
| 魔搭社区 | modelscope | ✅ 自动填充 | ✅ 自动填充 |
| DeepSeek | deepseek | ✅ 自动填充 | ✅ 自动填充 |
| 阿里云（通义千问） | dashscope | ✅ 自动填充 | ✅ 自动填充 |
| Moonshot（月之暗面） | moonshot | ✅ 自动填充 | ✅ 自动填充 |
| 智谱 | zhipu | ✅ 自动填充 | ✅ 自动填充 |
| 火山引擎 | volcengine | ✅ 自动填充 | ✅ 自动填充 |
| 硅基流动 | siliconflow | ✅ 自动填充 | ✅ 自动填充 |
| MiniMax | minimax | ✅ 自动填充 | ✅ 自动填充 |
| 百川 | baichuan | ✅ 自动填充 | ❌ 需手动输入 |
| 阶跃星辰 | stepfun | ✅ 自动填充 | ❌ 需手动输入 |
| 零一万物 | lingyi | ✅ 自动填充 | ❌ 需手动输入 |
| 腾讯混元 | tencent | ✅ 自动填充 | ❌ 需手动输入 |

**模型配置项（每个 Provider）**：

| 字段 | 说明 |
|------|------|
| 名称 | 用户自定义名称（如"我的 DeepSeek"） |
| 服务商 | 从 12 家预设中选择 |
| 协议 | OpenAI 或 Anthropic |
| Base URL | 服务商 API 地址（选择预设后自动填充） |
| API Key | 真实上游 API 密钥（保存后脱敏显示） |
| 模型名称 | 如 deepseek-chat、qwen-max 等 |
| 启用状态 | 控制该模型是否参与网关转发 |

**模型管理操作**：

| 操作 | 说明 |
|------|------|
| 添加模型 | 打开表单，选择预设或手动填写 |
| 编辑模型 | 修改已有模型配置（API Key 可留空不覆盖） |
| 删除模型 | 移除配置，若为当前默认则自动切换 |
| 设为默认 | 设置为当前活跃模型，网关优先使用 |
| 启用/禁用 | 控制模型是否参入网关转发 |
| 测试连接 | 用真实 API Key 检查上游是否可用 |
| 一键测试全部 | 逐个测试所有已启用模型 |

**交互细节**：
- API Key 保存后在前端始终脱敏显示（如 `sk-****abcd`）
- 编辑时可留空 API Key，不会覆盖原值
- 禁用当前默认模型时，自动切换到下一个启用的模型
- 未启用的模型不能设为默认

### 2.3 客户端接管

让 Claude Code 和 Codex 自动将请求指向本地 SUGT 网关，无需用户手动配置环境变量。

**支持接管的客户端**：

| 客户端 | 设置的环境变量 | 说明 |
|--------|---------------|------|
| Claude Code | `ANTHROPIC_BASE_URL` + `ANTHROPIC_AUTH_TOKEN` | 指向本地网关，使用 dummy key |
| Codex | `OPENAI_BASE_URL` + `OPENAI_API_BASE` + `OPENAI_API_KEY` | 指向本地网关 |

**接管操作**：

| 操作 | 说明 |
|------|------|
| 一键接管 | 写入 Windows 用户环境变量（setx） |
| 关闭接管 | 清除 SUGT 设置的环境变量 |
| 状态查看 | 显示当前各客户端的接管状态 |
| 生成启动脚本 | 生成 `claude-sugt.cmd` / `codex-sugt.cmd` |

**安全设计**：
- 客户端环境变量中只设置本地 dummy key（`sugt-local-key`），不暴露真实上游 API Key
- 自动检测 `ANTHROPIC_API_KEY` 与 `ANTHROPIC_AUTH_TOKEN` 冲突并提示

### 2.4 流量统计（Traffic Panel）

实时展示网关的流量情况，帮助用户了解使用状况。

| 指标 | 说明 |
|------|------|
| 累计请求数 | 网关启动以来的总请求数 |
| 今日请求数 | 当日累计请求数 |
| 成功率 | 成功请求占比 |
| 平均延迟 | 请求的平均响应时间（毫秒） |
| Token 用量 | 累计/今日的输入+输出 Token 数 |
| 失败的请求 | 失败请求的具体信息 |
| 活跃客户端 | 最近发起请求的客户端列表 |
| 小时级柱状图 | 近 60 分钟每分鐘请求量 |

注意：流量统计数据为内存存储，网关重启后归零。

### 2.5 日志查看

实时查看网关运行日志，便于排查问题。

| 功能 | 说明 |
|------|------|
| 日志显示 | 读取本地日志文件，最多显示 500 行 |
| 刷新 | 手动刷新获取最新日志 |
| 空态提示 | 无日志时显示"暂无日志" |
| 自动滚动 | 新日志自动滚到底部 |

### 2.6 系统托盘

GUI 最小化后，在系统托盘区常驻运行。

| 操作 | 说明 |
|------|------|
| 查看状态 | 显示服务状态、模型状态、接管状态、版本 |
| 启动/停止网关 | 直接托盘操作 |
| 打开配置目录 | 快速跳转到 `.sugt` 配置目录 |
| 接管开关 | 切换客户端接管状态 |
| 退出 | 完全退出应用 |

### 2.7 CLI 命令行工具

`sugt-cli.exe` 提供不依赖 GUI 的完整操作能力。

| 子命令 | 功能 | 使用示例 |
|--------|------|---------|
| `status` | 查看运行状态和配置 | `sugt-cli status` |
| `init` | 初始化配置 | `sugt-cli init --base-url <url> --api-key <key> --model <model>` |
| `serve` | 启动网关服务 | `sugt-cli serve --host 0.0.0.0 --port 8787` |
| `test` | 测试所有 Provider 连接 | `sugt-cli test` |
| `env status` | 查看接管状态 | `sugt-cli env status` |
| `env install` | 开启接管 | `sugt-cli env install` |
| `env uninstall` | 关闭接管 | `sugt-cli env uninstall` |
| `env print` | 打印环境变量脚本 | `sugt-cli env print` |
| `env repair` | 修复接管配置 | `sugt-cli env repair` |

CLI 和 GUI 共享同一套配置和数据，可混合使用。

### 2.8 开机自动启动

可配置是否随 Windows 开机自动启动（通过注册表 HKCU 实现）。

### 2.9 技能商店（商店版特有）

商店版在功能版基础上，增加了技能（Skill）管理能力，让用户可以安装社区 Claude Skills。

**技能生命周期**：

```
发现技能 → 安装（暂存区） → 挂载到 Claude → 使用
                                  ↓
                              取消挂载 → 卸载
```

**核心功能**：

| 功能 | 说明 |
|------|------|
| 仓库管理 | 添加/删除/刷新 Git 仓库（默认预置 4 个社区仓库） |
| 发现技能 | 浏览仓库中的可用技能，支持搜索 |
| 安装技能 | 从仓库安装到本地暂存区 |
| 卸载技能 | 从暂存区移除 |
| 挂载技能 | 将技能挂载到 Claude 技能目录（`.claude/skills/`） |
| 取消挂载 | 从 Claude 技能目录移除 |
| 插件只读列表 | 查看已安装的 Claude 插件（不支持在线安装） |
| GitHub 代理 | 配置加速前缀，解决国内网络访问 GitHub 问题 |
| 编辑器设置 | 配置打开技能目录的编辑器命令 |

**预置技能仓库**：

| 仓库 | 说明 |
|------|------|
| ComposioHQ/awesome-claude-skills | 社区技能合集 |
| JimLiu/baoyu-skills | 包子技能集 |
| anthropics/skills | Anthropic 官方技能 |
| cexll/myclaude | Claude 技能集 |

## 3. 辅助功能

### 3.1 配置目录

- 默认路径：`Documents\.sugt\`（我的文档下）
- 可通过环境变量 `SUGT_CONFIG_DIR` 自定义
- 可从 GUI 一键跳转打开

### 3.2 关于页面

- 显示产品名称、版本号、构建 ID
- 显示配置目录和日志文件路径
- 试用版显示有效期信息
- 自用版显示"无有效期限制"

### 3.3 配置初始化

- 首次启动自动创建配置目录和 `config.toml`
- 读取环境变量 `SUGT_DEFAULT_BASE_URL` + `SUGT_DEFAULT_API_KEY` + `SUGT_DEFAULT_MODEL` 可自动创建默认模型配置
- 默认监听地址：`127.0.0.1:8787`

### 3.4 URL 规范化

- OpenAI 协议：Base URL 自动补齐 `/v1` 后缀
- Anthropic 协议：保留原始 URL，不追加 `/v1`

## 4. 试用版治理机制

### 4.1 有效期控制

- 试用版有编译期注入的有效期（当前：2026-07-13）
- 到期后无法启动网关
- 界面显示到期提示"请联系作者获取新版"

### 4.2 机器绑定

- 首次运行时记录机器指纹（基于计算机名、用户名、硬件 GUID 的哈希）
- 更换机器后无法使用（需联系作者重新签发）

### 4.3 时钟防篡改

- 检测系统时间回滚（比上次运行时间早 10 分钟以上则判定异常）

### 4.4 自用版 vs 试用版

| 维度 | 自用版 | 试用版 |
|------|--------|--------|
| 有效期 | 无限制 | 30 天 |
| 机器绑定 | 无 | 有 |
| 关于页展示 | "内部自用版本" | "内部试用版本，有效期至 yyyy-MM-dd" |

## 5. 安全与隐私

| 关注点 | 措施 |
|--------|------|
| API Key 保护 | 前端只显示脱敏值，网关日志不记录完整 Key |
| 客户端环境变量 | 只设本地 dummy key，不暴露真实上游 Key |
| 配置文件 | 保存在用户文档目录，不进入代码仓库 |
| CORS 策略 | 当前允许所有来源（内网使用，需评估风险） |
| 运行时文件 | 不写入 exe 所在目录，状态文件仅在 `.sugt` 目录 |

## 7. 业务流程图

### 7.1 用户首次使用流程

```
下载便携包 → 解压 → 启动 SUGT.exe
  ↓
自动创建配置目录（Documents/.sugt/）
  ↓
进入模型配置页 → 点击"添加模型"
  ↓
选择服务商预设 → 填写 API Key → 保存
  ↓
返回控制台 → 点击"启动网关"
  ↓
进入客户端页 → 点击"一键接管"
  ↓
在终端中正常使用 Claude Code / Codex
  ↓
所有请求自动经过 SUGT 转发到配置的上游模型
```

### 7.2 请求转发流程

```
Claude Code / Codex
  ↓ HTTP 请求（127.0.0.1:8787）
SUGT 网关
  ↓ 路径路由分发
  ├── /v1/messages → Anthropic 协议处理
  │   ├─ Provider 是 Anthropic 协议 → 直接转发
  │   └─ Provider 是 OpenAI 协议 → 协议转换后转发
  ├── /v1/chat/completions → OpenAI 协议处理
  └── /health → 健康检查
  ↓
上游 LLM API（如 DeepSeek / 通义千问）
  ↓
响应流经 SUGT（记录统计） → 返回客户端
```
